#+TITLE: checkpassword-dovecot

* NAME
checkpassword-dovecot - bridge qmail-smtpd SMTP-AUTH to dovecot's auth-client

* SYNOPSIS
*checkpassword-dovecot* /subprogram/ [ /args/ ... ]

* DESCRIPTION
*checkpassword-dovecot* is a DJB-style /checkpassword/ program. It is not run
interactively: =qmail-smtpd= exec()s it once per SMTP-AUTH attempt, after
STARTTLS, with the credentials written on file descriptor 3 in the classic
=<authcid>\0<password>\0<timestamp>\0= format. The DSMR submission service
invokes it as

: qmail-smtpd checkpassword-dovecot /bin/true

so /subprogram/ is the program execed on success (conventionally =/bin/true=).

Instead of consulting a password database of its own, the bridge connects to
dovecot's auth-client protocol over a Unix socket and asks dovecot to
adjudicate the credential with =AUTH PLAIN service=smtp=. Dovecot's already
chained passdbs — vpopmail SQL, then =/etc/dovecot/system-passwd=, then PAM —
decide. This makes one dovecot passdb stack the single source of truth for both
IMAP login and SMTP submission, so a curated system user can relay through the
host even though =vchkpw= knows only vpopmail virtual accounts.

Only AUTH PLAIN and AUTH LOGIN are handled; both reduce to the same PLAIN
exchange with dovecot. CRAM-MD5 is not implemented because the DSMR stack does
not advertise it.

The socket path =/var/run/dovecot/auth-client-smtp= is compiled in. It is a
second listener (mode =0660=, owner =vpopmail:vchkpw=) added by this package's
dovecot conf snippet, because the default auth-client socket is owned
=dovecot:root= and unreadable by the vpopmail UID the bridge runs under.

* EXIT STATUS
A checkpassword program signals its verdict to qmail-smtpd by its exit code:

- *0* :: dovecot returned =OK=; the bridge exec()s /subprogram/ and qmail-smtpd
  accepts the AUTH (=235=).
- *1* :: dovecot returned =FAIL= (bad credentials or no passdb matched); a clean
  reject (=535 authentication failed=).
- *111* :: transient/internal error — a hung or unreachable dovecot, a timeout,
  or an unexpected reply; qmail-smtpd reports a temporary failure (=454=).

* FILES
- =/var/run/dovecot/auth-client-smtp= :: the dovecot auth-client listener the
  bridge connects to; created by =/etc/dovecot/conf.d/99-dsmr-smtp-auth.conf=.
- =/etc/dovecot/system-passwd= :: the system-user allow-list dovecot's
  passwd-file passdb reads; managed with *dsmr-smtpauth(8)*.

* SECURITY
The bridge processes only the trusted FD3 payload from qmail-smtpd and the
local dovecot socket; it never reads untrusted network input directly. It
bounds-checks the FD3 payload (max 512 bytes, NUL-separator validation, control
characters in the username rejected), applies a 10-second send/receive timeout
so a hung dovecot cannot tie up a worker, and never logs credentials. Any
unexpected reply from dovecot is treated as a transient error, never as
success.

*dsmr-smtpauth(8)*, *qmail-smtpd(8)*, *dovecot(1)*

For the theory of operation, the wire protocol, configuration, and debugging
hints, see the /dsmr-checkpassword-dovecot/ info manual
(=info dsmr-checkpassword-dovecot=) or the stack documentation website.
